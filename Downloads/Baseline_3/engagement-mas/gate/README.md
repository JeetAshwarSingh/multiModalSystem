# Synchronization Gate

The **SyncGate** aggregates modality results (Macro, rPPG, MER) for each video clip.
It is keyed by a deterministic ``clip_id`` generated by each block. The gate
behaviour follows the specification:

1. When the *first* result for a given ``clip_id`` arrives, a **collection window**
   opens and a timer starts (default ``timeout: 60`` seconds, configurable via
   ``gate.yaml``).
2. If **all three** modalities are received before the timeout, the gate emits the
   **bundle** immediately (early release).
3. If the timeout expires, the gate releases whatever modalities have arrived.
4. The bundle contains:
   * ``features`` – a dict ``modality -> features``
   * ``predictions`` – a dict ``modality -> predictions``
   * ``quality_metrics`` – a dict ``modality -> quality_metrics``
   * ``availability`` – a dict ``modality -> bool`` indicating which modalities
     are present (missing modalities are **not** zero‑filled).
5. After a bundle is released, any subsequent results for the same ``clip_id``
   are logged in ``late_results`` and discarded.
6. Duplicate results for the same modality are ignored (the first arrival is
   kept) and a warning is emitted.
7. If a modality reports ``status == "failed"`` it is treated as **absent**.

The gate is deterministic: given the same sequence of arrivals it will produce
the same bundles. It is implemented as a lightweight class that can be used in
the main pipeline or in unit tests.

## Usage example
```python
from gate.sync_gate import SyncGate

gate = SyncGate(timeout=60)
# Each block calls ``gate.receive(result)`` where ``result`` follows the common interface
bundle = gate.receive(result_macro)   # returns None until bundle is ready
bundle = gate.receive(result_rppg)    # may return a bundle early if all arrived
# After some time, if not all modalities arrived, call ``gate.check_timeout()``
# to force release of pending bundles.
```

## Configuration
The gate reads ``configs/gate.yaml`` (see that file) for ``timeout`` and optional
logging options.
