# Training & Evaluation Commands for Engagement‑MAS (Windows)

## 1️⃣ Environment setup (once)
```bash
# Create a conda environment (or use venv)
conda create -n engagement-mas-windows python=3.10 -y
conda activate engagement-mas-windows
```

## 2️⃣ Install dependencies
```bash
# Install generic CPU/CPU‑only packages
pip install -r requirements-windows.txt

# If you have an NVIDIA GPU and want CUDA acceleration, install matching wheels:
# (example for CUDA 11.8 – adjust version if you have a different toolkit)
python - <<'PY'
import subprocess, sys
subprocess.check_call([sys.executable, "-m", "pip", "install",
    "torch==2.2.0+cu118",
    "torchvision==0.17.0+cu118",
    "torchaudio==2.2.0+cu118",
    "-f", "https://download.pytorch.org/whl/torch_stable.html"])
PY
```

> **Note**: The `requirements-windows.txt` file (generated by the assistant) already lists all other required libraries (`pandas`, `numpy`, `mediapipe`, `opencv‑python‑headless`, `timm`, `torchmetrics`, `pytorch‑lightning`, `tqdm`, `scikit‑learn`, …). Install them with the first `pip install -r …` command.

## 3️⃣ Define project root (optional)
```bash
# PowerShell
$env:PROJECT_ROOT = (Resolve-Path .).Path
# cmd.exe
set PROJECT_ROOT=%cd%
# Bash (Git Bash, WSL, etc.)
export PROJECT_ROOT=$(pwd)
```
The code automatically expands `${PROJECT_ROOT}` in `configs/datasets.yaml`.

## 4️⃣ Training the Macro block
```bash
python -m training.train_macro \
    --config configs/training.yaml \
    --dataset daisee \
    --split train
```
The script will pick the best available device (CUDA → CPU). Check the console output for the selected accelerator.

## 5️⃣ Evaluation (choose a fusion strategy)
```bash
# Static Late Fusion (baseline)
python -m evaluation.evaluate \
    --config configs/fusion.yaml \
    --dataset daisee \
    --split test \
    --fusion static

# Agentic Fusion (adaptive weights)
python -m evaluation.evaluate \
    --config configs/fusion.yaml \
    --dataset daisee \
    --split test \
    --fusion agentic

# Early Fusion (deterministic projection)
python -m evaluation.evaluate \
    --config configs/fusion.yaml \
    --dataset daisee \
    --split test \
    --fusion early
```
Add `--disable-modality macro rppg mer` if you want to mask a specific modality.

## 6️⃣ Quick sanity‑check (run only a few clips)
```bash
python -m evaluation.evaluate \
    --config configs/fusion.yaml \
    --dataset daisee \
    --split test_quick \
    --fusion static \
    --max-clips 10
```
Useful for debugging before launching a full run.

## 7️⃣ Results & Research Paper Visualizations
Running evaluation automatically saves individual modality predictions (`macro`, `rppg`, `mer`), all fusion outputs (`early`, `static`, `agentic`), and summary metrics to `resultAndAnalysis/`.

It also generates publication-ready figures (300 DPI) and an IEEE/ACM LaTeX table inside `resultAndAnalysis/Analysis/`:
* `fig1_modality_vs_fusion_accuracy.png` (Accuracy across all individual modalities and fusions)
* `fig2_fusion_methods_comparison.png` (Multi-metric comparison of Early, Static, and Agentic)
* `fig3_per_class_f1_comparison.png` (F1-score across all 4 engagement classes)
* `fig4_confusion_matrices.png` (Side-by-side confusion matrix heatmaps)
* `fig5_agentic_modality_weights.png` (Adaptive weight distributions)
* `fig6_radar_performance_profile.png` (Trade-off radar profile)
* `paper_summary_table.tex` (LaTeX table ready for inclusion in paper)

To regenerate or update figures at any time from saved predictions:
```bash
python -m evaluation.generate_analysis --dir ../resultAndAnalysis
```

---
**All commands assume you are inside the project root** (`.../Baseline_3/engagement-mas`). Adjust paths if you run from elsewhere.
